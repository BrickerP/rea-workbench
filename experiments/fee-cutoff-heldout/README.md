# Fee-cutoff held-out check

This synthetic experiment asks a narrow question: does the fee recoverer infer
the surcharge cutoff, or does it reproduce the cutoff already encoded in the
implementation?

The tested source is pinned to commit
`f334078b7752cbca47afba6c97db2ec4a0d8cf2c`. The script verifies the six tested
files byte-for-byte against that commit before and after execution. Experiment
files may be present in the checkout; they are not part of the system under
test.

## Design

- The original fixture contains 24 rows but 23 unique `(amount, tier)` inputs.
- Controlled training uses 8 amounts across 3 tiers: 24 rows.
- Held-out evaluation uses 12 different amounts across 3 tiers: 36 rows.
- The synthetic oracle changes only the surcharge cutoff, from `$50` to `$60`.
- The existing pipeline and gate run unchanged. The emitted Python is also
  executed directly to measure training and held-out fit when the gate rejects.

This is a deterministic synthetic check. It uses no model calls or production
data and is not an LLM benchmark.

## Results

| condition | pipeline gate | training fit | held-out fit |
| --- | ---: | ---: | ---: |
| original fixture, `$50` oracle | pass | 24/24 | 36/36 |
| controlled training, `$50` oracle | pass | 24/24 | 36/36 |
| controlled training, `$60` oracle | reject (confidence 0.5) | 21/24 | 24/36 |

The result supports a limited conclusion: held-out success at `$50` does not by
itself demonstrate cutoff discovery, because the recoverer contains an explicit
`amount >= 50` split. The `$60` condition does not establish that the gate made
an incorrect decision; it records the unchanged gate decision and separately
measures the emitted code.

## Reproduce

From a checkout containing the pinned source snapshot:

```bash
python3 experiments/fee-cutoff-heldout/run.py \
  --repo . \
  --output experiments/fee-cutoff-heldout/results.json
python3 -m unittest experiments/fee-cutoff-heldout/test_run.py -v
```

The checked-in [`results.json`](results.json) is generated by the first command.
